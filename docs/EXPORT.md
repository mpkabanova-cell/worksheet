# Экспорт рабочего листа в Word

Документ описывает **технологию экспорта**: что происходит от данных листа до файла `.docx`, какие подходы используются и как обрабатывается каждый тип задания.

---

## Что такое экспорт в нашем случае

Пользователь нажимает «Скачать» — браузер **сам** собирает Word-файл и отдаёт его на диск или в виде бинарного объекта (`Blob`). Сервер приложения в этом не участвует: он только раздаёт фронтенд.

Файл `.docx` — это не «настоящий бинарный Word», а **ZIP-архив** с XML внутри (стандарт Office Open XML). Сборкой занимается npm-библиотека **docx**: она создаёт абзацы, таблицы, формулы, картинки и упаковывает всё в `.docx`.

Экран редактора (React) **не копируется** в Word напрямую. Экспорт **заново строит** тот же смысл и тот же вид, но другими средствами — часть как редактируемый текст Word, часть как вставленные картинки.

---

## Что подаётся на вход

На вход — JSON рабочего листа. Упрощённо:

```json
{
  "topic": "Квадратные уравнения",
  "subject": "Алгебра",
  "intro": "Квадратное уравнение — это уравнение вида $ax^2 + bx + c = 0$…",
  "pages": 2,
  "showAnswers": false,
  "showDifficulty": true,
  "print": {
    "answersSeparate": false,
    "orientation": "portrait"
  },
  "blocks": [
    {
      "type": "short_answer",
      "page": 0,
      "question": "Запишите общую формулу квадратного уравнения.",
      "correctAnswers": ["$ax^2 + bx + c = 0$"],
      "answerAreaStyle": "cells",
      "answerLines": 10
    },
    {
      "type": "ordering",
      "page": 0,
      "question": "Упорядочьте шаги решения.",
      "orderItems": ["Вычислить дискриминант", "Найти корни", "…"],
      "correctAnswers": ["3", "2", "1", "4"]
    },
    {
      "type": "page_break",
      "page": 0
    }
  ]
}
```

Перед экспортом JSON **нормализуют**: подставляют дефолты, чинят устаревшие форматы, проверяют целостность блоков (например, что у matching есть пары). Без этого в Word могут попасть битые или пустые задания.

---

## Что получается на выходе

Один `.docx` с одной секцией:

- поля страницы (отступы от края);
- ориентация — книжная или альбомная;
- содержимое — цепочка абзацев и таблиц Word.

Имя файла берётся из темы листа.

---

## Общая схема сборки

```
JSON листа
    │
    ├─ нормализация данных
    │
    ├─ чтение настроек печати
    │     · показывать ответы или нет
    │     · показывать сложность (звёзды)
    │     · ответы на отдельном листе или в том же
    │     · ориентация страницы
    │
    ├─ ожидание шрифтов в браузере (Arial, Cambria Math)
    │
    ├─ сборка содержимого (один или два прохода — см. ниже)
    │     │
    │     ├─ шапка листа (ученик, название, вводный текст)
    │     ├─ для каждой страницы:
    │     │     все блоки этой страницы по порядку
    │     └─ номер страницы (если страниц больше одной)
    │
    ├─ упаковка в Document (библиотека docx)
    │
    └─ Packer.toBlob → файл .docx
```

На время одного экспорта держат **кэш**: уже нарисованные формулы, загруженные картинки, уже снятые PNG-виджеты. Повторное использование ускоряет сборку и не дублирует работу.

---

## Два способа положить контент в Word

Это главное техническое разветвление. Не каждый тип задания рисуется одинаково.

### Способ 1 — нативный Word (текст, таблицы, формулы)

Подходит там, где в Word можно нормально описать содержимое XML-элементами:

- абзацы с разным начертанием;
- таблицы;
- **OMML** — язык формул Word (формула остаётся редактируемой в Word, не картинкой).

**Как обрабатывается строка с текстом и формулами:**

1. Текст разбирается как упрощённый Markdown: жирный, курсив, зачёркнутый, подчёркнутый, код, абзацы.
2. Фрагменты `$...$` и `$$...$$` выделяются как LaTeX.
3. LaTeX сначала переводится в OMML (Office Math Markup Language).
4. Если перевод не удался — формула рисуется через KaTeX в PNG и вставляется как картинка в строку.

Пример: вопрос «Чему равен $x$ при $a = 2$?» в Word превращается в один абзац: обычный текст + объект формулы + снова текст + формула.

**Через этот способ идут:** вводный текст, формулировки вопросов, блок «просто текст», текст с пропусками, текстовые варианты ответа (один/несколько), подписи.

### Способ 2 — картинка (PNG) внутри Word

Подходит для сложной вёрстки, которую в Word трудно или невозможно повторить один в один с экраном:

- сопоставление (две колонки, линии между парами);
- упорядочивание (строки с клетками для номеров);
- группировка (таблица + слова под ней);
- поле для ответа (линии, клетчатка, оси координат).

**Как это работает:**

1. В памяти браузера собирается HTML-страница с теми же стилями, что на экране (шрифты, цвета, отступы, KaTeX для формул в ячейках).
2. Эту страницу **не показывают** пользователю — она монтируется за пределами видимой области.
3. Библиотека **html-to-image** делает снимок (PNG) этого HTML.
4. PNG вставляется в Word как **ImageRun** — обычная картинка в документе.

Плюс: вид в Word совпадает с прототипом. Минус: содержимое виджета в Word не редактируется как текст — только как изображение.

**Картинки в вариантах ответа** (когда в choice картинки, а не текст) загружаются отдельно: из data-URL или по HTTP, если сервер отдаёт CORS.

## Как устроен лист в Word

### Шапка листа

Сверху каждого «прохода» сборки:

| Элемент | Когда есть |
|---------|------------|
| «Ученик: ________» | лист создан через ИИ (не вручную) |
| Название темы | всегда |
| Вводный текст (intro) | если включён и не пустой |

Intro и заголовок — через текстовый пайплайн (Markdown + LaTeX → Word).

### Страницы и разрывы

Лист может быть многостраничным. У каждого блока в JSON указан номер страницы. Блок типа «разрыв страницы» вставляет в Word принудительный перенос.

Между страницами — элемент PageBreak. Внизу страницы может быть номер («Страница 2 из 3»), если страниц больше одной.

### Нумерация заданий

Номера «1.», «2.»… получают только **задания**. Не нумеруются:

- просто текст;
- блок «медиа / QR»;
- разрыв страницы.

Номер — порядковый среди заданий на всех предыдущих страницах и текущей.

### Рамка одного задания

Каждое нумерованное задание — **таблица Word** без видимых границ:

```
┌──────┬─────────────────────────────────────────┐
│  1   │  Формулировка (текст + формулы)         │
│      │  Сложность: ★★☆  (если включено)        │
├──────┴─────────────────────────────────────────┤
│  тело задания (варианты, виджет, пропуски…)   │
└────────────────────────────────────────────────┘
```

Слева — номер, справа — вопрос. Ниже — содержимое задания. У части типов (сопоставление, упорядочивание, группировка, текстовый выбор ответа) тело **встроено в эту же таблицу**; у других — идёт отдельным блоком под таблицей.

## Настройки, которые меняют содержимое файла

| Настройка | Эффект |
|-----------|--------|
| Показать ответы | ключ: зелёный текст, отмеченные варианты, линии в matching, номера в ordering и т.д. |
| Показать сложность | под вопросом строка «Сложность» и звёзды (картинки) |
| Ответы на отдельном листе | в одном файле **два** листа подряд: сначала для ученика, потом раздел «Ответы» с ключом |
| Ориентация | книжная / альбомная |
| Предмет (`subject`) | влияет на вид поля для краткого ответа: линии, клетки, оси |

Количество копий при печати из интерфейса **на содержимое Word не влияет** — только на печать в браузере.

---

## Два листа в одном файле («ответы отдельно»)

Если включено «ответы на отдельном листе»:

**Проход 1 — лист ученика.** Все задания **без** ответов, даже если в настройках листа ответы включены.

**Разрыв страницы + заголовок «Ответы».**

**Проход 2 — ключ.** Тот же лист, те же блоки, но везде режим «с ответами».

Если эта опция выключена — один проход, и ответы видны или нет согласно общей галочке «показать ответы».

## Как обрабатывается каждый тип задания

### Краткий / развёрнутый ответ

- Формулировка — текстовый пайплайн (Word).
- Под вопросом — **PNG поля для ответа** (способ 2).
- Вид поля: горизонтальные линии, клетчатка, пустой прямоугольник, координатные оси, числовая прямая — зависит от настройки блока и предмета.
- Лист ученика: поле пустое. Ключ: в поле зелёным написан правильный ответ.

### Один или несколько вариантов ответа

**Только текст:** каждый вариант — абзац с маркером (кружок или квадрат, тоже PNG) и текстом. Варианты могут быть **внутри** таблицы задания.

**С картинками:** под вопросом — таблица Word с ячейками-картинками. В ключе у верных вариантов зелёная рамка.

Текст варианта поддерживает формулы через OMML/PNG.

### Заполнить пропуски

- Вопрос — текстом в Word.
- Основной текст с пропусками — текстом; пропуски на листе ученика — символы подчёркивания, не «поля Word».
- В ключе на месте пропусков подставляются слова из массива ответов, зелёным.
- **Банк слов под заданием в Word не выводится** — только текст с пропусками.

### Сопоставление

- Вопрос — текстом.
- Пары «слева / справа» — **одна PNG-картинка** (способ 2).
- Лист ученика: две колонки, без линий между парами.
- Ключ: линии между правильными парами, подсветка.

Элементы могут быть текстом или картинками (картинки подгружаются в браузере).

### Упорядочивание

- Вопрос — текстом.
- Список элементов с клетками для номеров — **PNG**.
- Лист ученика: элементы в сохранённом порядке, клетки пустые.
- Ключ: в клетках зелёные номера правильной последовательности.

### Группировка (таблица)

- Вопрос — текстом.
- Таблица с заголовками колонок и ячейками — **PNG**.
- Под таблицей на листе ученика — **банк слов** (простой список, без рамок, с отступами).
- Ключ: в ячейках зелёным написаны ответы; банк на ключе не нужен.

### Просто текст

- Абзацы из поля `body`, серым цветом. Без номера задания.

### Медиа / QR

- Подпись и QR-код (картинка). Без номера задания.

### Разрыв страницы

- Принудительный перенос на новую страницу Word.

## Текст и формулы — подробнее

**Markdown в строках:** `**жирный**`, `*курсив*`, `~~зачёркнутый~~`, `<u>подчёркнутый</u>`, `` `код` ``, пустая строка = новый абзац, `---` = разделитель.

**LaTeX:** inline `$x^2$`, блочный `$$...$$`.

**Перевод LaTeX в Word (OMML):** поддерживаются дроби, корни, степени и индексы, скобки `\left( \right)`, базовая тригонометрия, греческие буквы, умножение `\cdot`. Сложные конструкции (`\sum`, `\int`, `\lim`, битые `\left`) уходят в **PNG через KaTeX** — в Word это уже картинка, не редактируемая формула.

**Цвета:**

- основной текст — тёмно-синий `#161A33`;
- второстепенный (intro, подписи) — `#656C94`;
- правильные ответы — зелёный `#0DB56C`;
- линии и рамки — `#E4E6F7`.

**Шрифты:** Arial для текста, Cambria Math для формул Word. Перед экспортом браузер дожидается их загрузки — иначе снимки PNG и метрики текста «плывут».

**Ширина контента:** около 736 px логической ширины — как на экране в редакторе. В Word размеры пересчитываются в twips/dxa (единицы OOXML).

## Используемые технологии (сводка)

| Технология | Роль |
|------------|------|
| **Office Open XML / docx** | сборка `.docx` в браузере |
| **OMML** | редактируемые формулы в Word |
| **LaTeX → OMML** | перевод `$формул$` из данных листа |
| **KaTeX** | PNG-формулы, если OMML не справился; формулы внутри HTML-виджетов |
| **html-to-image** | HTML/CSS → PNG для виджетов |
| **DOM браузера** | невидимая отрисовка виджетов перед снимком |
| **fetch / data URL** | загрузка картинок вариантов и QR |

---

## Ограничения технологии

- **Только браузер.** Нужны `document`, `canvas`, загрузка шрифтов. На сервере без headless-браузера этот же код не выполнится.
- **Виджеты в Word — картинки.** Matching, grouping, ordering, поле ответа не редактируются в Word как таблицы — только как вставленные PNG.
- **Картинки по URL** должны быть доступны с CORS или переданы как `data:image/...;base64,...`.
- **Сложный LaTeX** частично превращается в картинки — это ожидаемое поведение, не ошибка экспорта.

## Пример: от данных до одного задания «сопоставление»

**Вход (фрагмент JSON):**

```json
{
  "type": "matching",
  "page": 0,
  "question": "Сопоставьте способ решения и описание.",
  "leftItems": [
    { "text": "Формула корней" },
    { "text": "Разложение на множители" }
  ],
  "rightItems": [
    { "text": "Через дискриминант" },
    { "text": "Если есть целые корни" }
  ],
  "correctAnswers": ["Формула корней → Через дискриминант", "Разложение на множители → Есть целые корни"]
}
```

**Что делает экспорт:**

1. Берёт формулировку вопроса → абзацы Word с формулами, если есть `$...$`.
2. Строит HTML: две колонки, стили как на экране, формулы через KaTeX в ячейках.
3. Если режим «ключ» — рисует SVG-линии между парами.
4. Делает PNG снимок HTML.
5. Вставляет PNG в таблицу задания под вопросом.
6. Добавляет отступ до следующего задания.

**В итоге в `.docx`:** номер, текст вопроса, одна картинка с таблицей сопоставления.

## Пример: упаковка в файл (идея кода)

Смысл финального шага — не «скачать HTML», а собрать объект документа и получить blob:

```javascript
import { Document, Packer, PageBreak, Paragraph, PageOrientation } from 'docx'

// children — массив абзацев и таблиц, собранный из всех блоков листа
const doc = new Document({
  sections: [{
    properties: {
      page: {
        margin: { top: 432, bottom: 432, left: 432, right: 432 },
        size: {
          orientation: PageOrientation.PORTRAIT,
        },
      },
    },
    children: [
      // шапка, задания, разрывы страниц…
      new Paragraph({ children: [new PageBreak()] }),
    ],
  }],
})

const blob = await Packer.toBlob(doc)
// blob — готовый .docx для скачивания или отправки на сервер
```

Вся сложность — в том, **как заполнить `children`**: это и есть описанная выше сборка по типам блоков, двум способам отрисовки и режимам «ученик / ключ».

## Экспорт PDF (1:1 с Word)

Кнопки **PDF** собирают **тот же `.docx`**, что и кнопка DOCX, и конвертируют его **в браузере** (без LibreOffice и без сервера):

1. `exportWorksheetDocxBlob` — та же сборка docx.
2. `docx-preview` отрисовывает файл в скрытый контейнер.
3. Страницы снимаются через `html2canvas` и складываются в PDF (`jspdf`).

Содержание совпадает с Word-экспортом, потому что источник один и тот же `.docx`. Сервер не участвует.
