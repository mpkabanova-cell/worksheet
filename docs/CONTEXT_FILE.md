# Извлечение текста из приложенного файла

Контракт для разработчиков: **что на входе, что на выходе, промпт для модели**. Как текст дальше используется в генерации — [`PROMPTS.md`](./PROMPTS.md).

---

## 1. Вход

**Фронт** отправляет файл при прикреплении на форме Create:

| Параметр | Значение |
|----------|----------|
| Метод | `POST /api/extract-context` |
| Тело | `multipart/form-data`, поле `file` |
| Форматы | `.docx`, `.pdf`, `.jpg`, `.jpeg`, `.png` |
| Размер | до 10 МБ |

Бинарник **не сохраняется** — только результат распознавания.

---

## 2. Выход

**Сервер** возвращает полную расшифровку **без суммаризации**:

```json
{
  "text": "...весь извлечённый текст...",
  "truncated": false
}
```

| Поле | Смысл |
|------|-------|
| `text` | Plain text, до 12 000 символов |
| `truncated` | `true`, если текст обрезан по лимиту |

**Фронт** записывает в черновик:

| Поле черновика | Откуда |
|----------------|--------|
| `contextFileName` | имя загруженного файла |
| `contextFileText` | `text` из ответа (или `undefined`) |
| `contextFileNote` | если `text` пустой — «файл приложён, текст не извлечён» |

При генерации листа `contextFileText` уходит в промпт как `reference_file.content` — файл повторно не загружается.

### Ошибки API

| HTTP | code | Когда |
|------|------|-------|
| 400 | `BAD_REQUEST` | Нет файла / неподдерживаемый формат |
| 413 | `PAYLOAD_TOO_LARGE` | Файл > 10 МБ |
| 503 | `NO_API_KEY` | PDF или изображение без ключа на сервере |
| 502 | `EXTRACT_ERROR` | Ошибка извлечения |

---

## 3. Между входом и выходом

По типу файла выбирается один из путей:

| Файл | Как извлекается | Модель |
|------|-----------------|------|
| `.docx` | Парсинг XML (JSZip) | **не вызывается** |
| `.pdf` с текстовым слоем ≥ 200 символов | pdf-parse | **не вызывается** |
| `.pdf`-скан, `.jpg`/`.png`, PDF с малым текстом | Страница/картинка → PNG → **OpenRouter vision-модель** | **вызывается** |

Для PDF-скана: до 3 страниц (настраивается `CONTEXT_PDF_MAX_PAGES`), тексты страниц склеиваются через `\n\n---\n\n`.

После любого пути — обрезка до 12 000 символов.

### Особенности

- **DOCX без ключа:** если сервер вернул 503, фронт сам парсит docx (упрощённо, без таблиц).
- **Картинки в vision OCR:** модель описывает их в `[квадратных скобках]`, не через `![](...)`. Если модель всё же вернула `![...](...)`, `stripMarkdownImages` удаляет такие фрагменты.
- **PDF с текстовым слоем:** встроенные иллюстрации **не извлекаются** — только текст подписей. Vision OCR при этом не вызывается.

---

## 4. Промпт для модели (vision OCR)

**Где:** `server/visionOcr.js` → `USER_PROMPT_VISION`  
**Когда:** PDF-скан, JPG/PNG, PDF без достаточного текстового слоя  
**Запрос:** `POST {OPENAI_BASE_URL}/chat/completions`, модель `qwen/qwen3-vl-235b-a22b-instruct` (`CONTEXT_OCR_MODEL`), `temperature: 0.1`

Сообщение user состоит из **текста промпта** + **image_url** (base64 data URL).

```
Распознай текст на изображении максимально точно.
Верни только результат без комментариев.
Сохрани структуру документа (абзацы, списки, таблицы).
Используй Markdown.
Все формулы запиши в LaTeX ($...$ и $$...$$). Если в формулах встречаются незнакомые операторы (например, arctg, пиши их в формулах через \operatorname{})

Картинки, фото, схемы, диаграммы, вставленные изображения и любые нетекстовые фрагменты на скриншоте
не воспроизводи как изображения: для каждого дай краткое описание в квадратных скобках.
Например: [логотип компании], [блок-схема], [скрин интерфейса кнопки].
Не используй синтаксис Markdown-картинок (![...](...)) и не вставляй ссылки на файлы или URL.
Не используй маркеры вида [РИС:1] и подобные — только обычные квадратные скобки с описанием.

Никаких пояснений до или после результата, только распознанный текст и описания в скобках.
```

**Что должна вернуть модель:** полный текст страницы в Markdown + LaTeX, без суммаризации и без комментариев. Ответ проходит `stripMarkdownImages` и попадает в `text` ответа API.

## 5. Пример: первая страница PDF «Задачи олимпиады»

Файл: PDF на 11 страниц (задачи для 5–6, 7–8 и старших классов). Ниже — что происходит с **первой страницей** при прикреплении к листу.

### 5.1. Что на странице

На первой странице — текстовая задача без встроенных иллюстраций:

- заголовок **«5–6 классы»**;
- условие про Смешариков (Бараш, Крош, Совунья, Ежик, Пин, Лосяш) и проход через Мышиную пещеру;
- список ограничений по времени (Совунья — 3 мин, Пин — 1 мин, …);
- блок **«Решение»** с пошаговым подсчётом: 1 + 1 = 2, + 3 = 5, … → **18 минут**.

Картинок на этой странице нет. На других страницах того же файла (задача про молочный комбинат) есть **схемы графов** — см. [§ 5.4](#54-картинки-что-с-ними-происходит).

### 5.2. Какой метод сработал

Система **не** рендерила первую страницу в PNG и **не** вызывала модель.

Причина: `pdf-parse` извлекает **весь текстовый слой PDF сразу** (все 11 страниц). Его длина больше порога **200 символов** — срабатывает быстрый путь без vision OCR.

```
PDF (11 стр.) → pdf-parse → текст ≥ 200 символов → вернуть text
                              (модель не вызывается)
```

### 5.3. Извлечение и преобразование

**Шаг 1 — сырой текстовый слой** (фрагмент первой страницы, как отдаёт `pdf-parse`):

```
5-6 классы
1. 	Бараш, Крош, Совунья, Ежик, Пин и Лосяш отправились в поход к Голубому озеру. Путь предстоял не
близкий и к вечеру друзья добрались до Чертовой скалы. Перед ними открылся вход в проходную
Мышиную пещеру. Проход был такой узкий, что проходить одновременно могли не больше двух
путешественников. Кроме того, без фонаря идти в темноте было опасно. Фонарь был только один.
Бараш был напуган и хотел идти непременно в первой паре. Какое наименьшее суммарное время
затратили друзья для преодоления пещеры, если
• 	Совунья пересекла пещеру за 3 минуты,
• 	Пин затратил 1 минуту,
• 	Бараш ни на шаг не отставал от Пина, он боялся остаться один в пещере,
• 	Крош затратил 2 минуты,
• 	Ежик вышел из пещеры через 3 минуты,
• 	Лосяша не могли дождаться 5 минут?
Решение:
18 минут.
1 минута
+1 минута = 2 минуты
+3 минуты = 5 минут
+1 минута = 6 минут
+5 минут = 11 минут
```

**Шаг 2 — обрезка:** `trim`, лимит 12 000 символов. В данном файле `truncated: false`.

**Шаг 3 — ответ API:**

```json
{
  "text": "5-6 классы\n1. \tБараш, Крош, Совунья...",
  "truncated": false
}
```

**Шаг 4 — черновик:** строка целиком (все 11 страниц) → `contextFileText`.

### 5.4. Страницы со схемами графов (стр. 4–9)

Для этого файла срабатывает **текстовый слой PDF**, модель **не вызывается**. Схемы графов — растровые картинки внутри PDF; `pdf-parse` их не видит.

**Что реально попадает в `text`** (фрагмент из ответа API):

```
Решение:
Создаем нагруженный граф с цифровой нумерацией вершин.

-- 4 of 11 --

Создаем ребра графа с весом по условиям времени проезда в минутах.
Из вершины 1 выбираем самый короткий путь – в вершину 2.
Из вершины 2 выбираем самый короткий путь – в вершину 4.

-- 5 of 11 --

Из вершины 4 выбираем самый короткий путь – в вершину 3.
Из вершины 3 выбираем самый короткий путь – в вершину 5.
...
```

| | |
|--|--|
| Текст условия и подписи к шагам решения | **Есть** |
| Сами схемы графов (вершины, рёбра, веса) | **Нет** — в `text` не попадают |
| `[описания картинок]` от vision OCR | **Нет** — OCR не вызывался |
| `stripMarkdownImages` | **Не вызывается** — некуда применять |

**Итог для этого PDF:** страница 1 и страницы 4–9 обрабатываются одним вызовом `pdf-parse` на весь документ. Модель и постобработка OCR на этом пути не участвуют.
