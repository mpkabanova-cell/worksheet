# Агент 0. Обработка файлов

Краткое описание агента, дата-контракты и промпт. Полный цикл генерации листа — в PDF «Академ. требования генерации рабочих листов»; агенты 1–2 — [`PLAN_AGENT.md`](./PLAN_AGENT.md), [`PROMPTS.md`](./PROMPTS.md).

---

## Функция агента

Переводит содержимое прикреплённого файла в текст для учёта контекста при генерации plan/worksheet. Используется OCR + multimodal vision.

На выходе получаем и сохраняем для следующих агентов **размеченный markdown + LaTeX** текст. Распознанный текст **не показывается** пользователю в UI — только имя файла.

| Функция агента | Модель по умолчанию | Fallback |
|----------------|---------------------|----------|
| Обработка файлов (extract + vision OCR) | Qwen3-VL (`qwen/qwen3-vl-235b-a22b-instruct`, env `CONTEXT_OCR_MODEL`) | задаётся тем же env при смене модели на OpenRouter |

*Fallback — запасная модель OpenRouter, если основная недоступна по внутренней ошибке провайдера.*

---

## Параметр формы «Прикреплённый файл»

| Параметр | Поле (UI / spec) | Поле (код) | Тип | Обязательность | Default | Допустимые значения / формат |
|----------|------------------|------------|-----|----------------|--------|------------------------------|
| Прикреплённый файл | `attached_file` | `contextFileName` + бинарник в сессии загрузки | `object \| null` | нет | `null` | **docx, pdf, jpg, png** — один файл до **10 МБ** |

После extract на бэке и фронте сохраняются служебные поля (не показываются учителю):

| Поле (код) | Тип | Содержание |
|------------|-----|------------|
| `contextFileText` | `string \| null` | Полный extract (markdown + LaTeX), до фильтрации |
| `contextFileNote` | `string \| null` | Пояснение, если текст не извлечён |

## Дата-контракт Агента 0

### Вход → выход (логический уровень)

| Вход | | Выход |
|------|---|-------|
| Прикреплённый файл | `attached_file` | Распознанный контекст для AI-агентов 1–2 |
| | | Сохраняется и повторно используется, пока не изменится текущий загруженный файл |
| | | Может содержать markdown + LaTeX |
| | | Иллюстративный материал описывается словами в `[квадратных скобках]` или опускается при фильтрации |
| | | **`source_content`** — отфильтрованный фрагмент для промптов (условия и данные, без решений/ответов) |

### Вход → выход (HTTP API)

#### Эндпоинт

`POST /api/extract-context`

| Вход | Тип | Описание |
|------|-----|----------|
| `file` | `multipart/form-data` | Один файл: `.docx`, `.pdf`, `.jpg`, `.jpeg`, `.png`, `.webp`, `.gif` |
| Размер | — | ≤ 10 МБ |

| Выход (успех) | Тип | Описание |
|---------------|-----|----------|
| `text` | `string` | Полный extract; обрезка по символам **отключена** |
| `truncated` | `boolean` | Всегда `false` (поле совместимости) |

| Выход (ошибка) | Тип | Описание |
|----------------|-----|----------|
| `error` | `string` | Код: `BAD_REQUEST`, `BAD_FORMAT`, `PAYLOAD_TOO_LARGE`, `EXTRACT_ERROR`, `PDF_EXTRACT_ERROR`, `NO_API_KEY` |
| `message` | `string` | Текст для UI |

### Вход → выход (промпты Агентов 1–2)

| Вход (из черновика) | Поле в user JSON | Выход |
|---------------------|------------------|-------|
| `contextFileText` + `grade` + `additionalWishes` (после фильтра) | **`source_content`** | `string \| null` — релевантный текст: условия и данные без решений/ответов, с `[описаниями]` иллюстраций из extract |

Имя файла, `filter_note`, `selected_block` и прочие метаданные фильтра **в промпт не передаются** — только строка `source_content`. Служебный объект `referenceFilePayload()` используется в технической пробе и логах.

**Модули:** `src/data/contextFile.ts` → `buildContextReference`, `sourceContentForDraft`; фильтрация — `src/data/contextFilter.ts`.

**Выбор блока для `source_content`:** по умолчанию — параллель формы или явный блок в пожеланиях. Если в `additional_wishes` указано использовать **весь материал документа** (и близкие формулировки), фильтр по классу **не применяется**: в `source_content` попадают все блоки extract (решения и ответы по-прежнему вырезаются). Агент 1 при этом распределяет задания по разным фрагментам файла; недостающие пункты дополняет аналогами в том же сюжете, а не посторонними темами.

## Техническая подготовка и AI-вызов

| Вход | Техническая подготовка | AI-вызов |
|------|------------------------|----------|
| **DOCX** | Обход `word/document.xml`; каждый inline-рисунок (`r:embed`) → PNG из `word/media/` | `Prompt_0` + изображение на каждый рисунок; текст параграфов/таблиц без OCR |
| **PDF** | `pdf-parse`: текстовый слой по страницам; на «разреженных» страницах — рендер в PNG | `Prompt_0` + PNG **только** где мало текста (`PDF_VISION_MODE=sparse`, по умолчанию) |
| **JPG / PNG** | Без преобразования | `Prompt_0` + изображение |

#### Параметры vision-запроса

| Параметр | Значение |
|----------|----------|
| Эндпоинт | `POST {OPENAI_BASE_URL}/chat/completions` |
| Модель | `CONTEXT_OCR_MODEL` |
| Temperature | `0.1` |
| Постобработка | `stripMarkdownImages()` — удаляет `![...]()` и `<img>`; `[описания]` сохраняет |

### Модели (OpenRouter)

| Решение | Модель | Роль | Env |
|---------|--------|------|-----|
| Qwen3-VL | `qwen/qwen3-vl-235b-a22b-instruct` | Основная для extract | `CONTEXT_OCR_MODEL` |
| — | — | Ключ API | `OPENAI_API_KEY` |
| — | — | Base URL | `OPENAI_BASE_URL` |

Генерация plan/worksheet (Агенты 1–2) использует **отдельную** модель `OPENAI_MODEL` (Gemini Flash) — не путать с Агентом 0.

### Prompt_0 (vision OCR)

**Где в коде:** `server/visionOcr.js` → `USER_PROMPT_VISION`

```
Распознай текст на изображении максимально точно.
Верни только результат без комментариев.
Сохрани структуру документа (абзацы, списки, таблицы).
Используй Markdown.
Все формулы запиши в LaTeX ($...$ и $$...$$). Если в формулах встречаются незнакомые операторы (например, arctg, пиши их в формулах через \operatorname{})

Картинки, фото, схемы, диаграммы, графики, карты, таблицы-изображения и любые нетекстовые фрагменты
не воспроизводи как изображения: для каждого дай описание в квадратных скобках.
Для графиков и диаграмм в [скобках] укажи оси, подписи, ключевые точки и значения, если они читаемы.
Для схем и блок-схем опиши связи и элементы кратко, но содержательно.
Не пропускай иллюстрации — каждая должна получить [описание].
Например: [график функции y=x^2, ось OX, OY, вершина в (0,0)], [блок-схема алгоритма с ветвлением].
Не используй синтаксис Markdown-картинок (![...](...)) и не вставляй ссылки на файлы или URL.
Не используй маркеры вида [РИС:1] и подобные — только обычные квадратные скобки с описанием.

Никаких пояснений до или после результата, только распознанный текст и описания в скобках.
```

## Логика повторного запуска

Как в product spec: при «Сгенерировать план» / «Создать» сравнивается загруженный файл на фронте с уже сохранённым `contextFileText`.

| Условие | Действие |
|---------|----------|
| Файл новый или заменён | Запуск Агента 0 → перезапись `contextFileText` → пересчёт `source_content` |
| Файл не менялся | Пропуск extract, используется сохранённый контекст |
| Изменились `subject`, `topic`, `grade`, `additional_wishes` | `source_content` пересчитывается из того же extract (другой блок/фильтр) |

## Примеры разметки текста и изображений

Итог Агента 0 — одна текстовая строка (`contextFileText`): **обычный текст** из документа + **`[описания]`** вместо картинок + **LaTeX** для формул (если их распознала vision-модель). Markdown-ссылки на файлы и `![картинки]()` в extract **не сохраняются**.

Ниже — как собирается разметка **по типу файла**.

---

### DOCX — текст из XML, картинки через vision

DOCX **не конвертируется в PDF**. Сервер (`docxVision.js`) читает `word/document.xml` по порядку блоков и для каждого inline-рисунка вызывает `Prompt_0`.

#### Абзац только с текстом

**В документе Word:** заголовок «5-6 классы», затем абзац с условием задачи.

**В extract (текст из `<w:t>`, без ИИ):**

```markdown
5-6 классы

Бараш, Крош и Совунья отправились в поход. Перед ними открылся вход в Мышиную пещеру. Совунья пересекла пещеру за 3 минуты. Пин затратил 1 минуту.
```

Абзацы разделяются **двойным переводом строки** (`\n\n`).

#### Текст и картинка в одном абзаце

**В документе Word:** после строки «Крош затратил 2 минуты» — inline-рисунок персонажа, затем продолжение текста.

**Шаг 1 — vision на PNG из `word/media/`** (сырой ответ модели):

```markdown
[мультяшная овечка розового цвета с фиолетовыми рогами, улыбается]
```

Если модель вернула текст без скобок → код оборачивает: `normalizeVisionDescription` → `[…]`.

**Шаг 2 — склейка в порядке документа** (`mergeParagraphParts`):

```markdown
Крош затратил 2 минуты.

[мультяшная овечка розового цвета с фиолетовыми рогами, улыбается]

Ежик вышел из пещеры через 3 минуты.
```

Текст до и после рисунка остаётся **текстом**; картинка — **отдельным блоком `[…]`** между абзацами, не `![image](…)`.

#### Таблица

**В документе Word:** таблица 2×2 с текстом в ячейках.

**В extract (ячейки через ` | `, строки — отдельные абзацы):**

```markdown
Персонаж | Время
Бараш + Пин | 1 мин
Крош + Ежик | 2 мин
```

Картинки внутри ячеек обрабатываются так же: текст ячейки + `[описание]`, если в ячейке был рисунок.

#### Дубли из text box (нормализация)

Word иногда дублирует содержимое text box в XML. Код схлопывает повтор:

| До (`normalizeTimelineLine`) | После |
|------------------------------|--------|
| `1 мин=2 мин1 мин=2 мин` | `1 мин = 2 мин` |

---

### PDF — текстовый слой + vision на «разреженных» страницах

Пайплайн: `pdf-parse` → при необходимости рендер страницы в PNG → `Prompt_0` (`PDF_VISION_MODE=sparse` по умолчанию: vision, если на странице < 120 символов текста).

#### Страница с плотным текстом (vision не вызывается)

**В PDF:** страница с набором задач, текстовый слой читается.

**В extract:**

```markdown
5-6 классы

1. Бараш, Крош и Совунья отправились в поход к Голубому озеру.

Совунья пересекла пещеру за 3 минуты.
Пин затратил 1 минуту.
```

#### Страница-скан или схема (мало текста → vision)

**В PDF:** одна большая схема, почти без текстового слоя.

**Vision возвращает:**

```markdown
[график маршрута: ось OX — время в минутах, точки A (1 мин), B (2 мин), C (3 мин)]

Формула времени: $T = t_1 + t_2 + t_3$
```

**В extract (sparse: дописывается к текстовому слою или заменяет его):**

```markdown
[график маршрута: ось OX — время в минутах, точки A (1 мин), B (2 мин), C (3 мин)]

Формула времени: $T = t_1 + t_2 + t_3$
```

#### Несколько страниц

Страницы склеиваются через разделитель:

```markdown
…текст страницы 1…

---

…текст страницы 2…
```

---

### JPG / PNG — весь файл через vision

Один файл = один вызов `Prompt_0`. Модель сама решает структуру: абзацы, списки, `[описания]` внутри рисунка на фото.

**Вход:** фото страницы учебника с задачей и диаграммой.

**В extract после `stripMarkdownImages`:**

```markdown
Задача 3. Найдите площадь треугольника.

Стороны: $a = 5$ см, $b = 8$ см, угол между ними $60°$.

[чертёж треугольника ABC: сторона AB подписана 5 см, BC — 8 см, угол B = 60°]
```

Если модель ошибочно вернула `![диаграмма](...)`, постобработка **удаляет** markdown-картинку; содержательное описание должно быть в `[скобках]` по инструкции `Prompt_0`.

---

### Постобработка vision-ответа

| Шаг | Где | Что делает | Пример |
|-----|-----|------------|--------|
| `normalizeVisionDescription` | `docxVision.js` | Оборачивает описание в `[…]`, если модель забыла скобки | `график y=x^2` → `[график y=x^2]` |
| `stripMarkdownImages` | `visionOcr.js` | Удаляет `![…](…)` и `<img>` | `Текст ![рис](url) дальше` → `Текст  дальше` |
| `mergeParagraphParts` | `docxVision.js` | Чередует текст и `[описания]` в порядке XML | см. пример «текст и картинка в одном абзаце» |
| `truncateContextText` | `extractContext.js` | Обрезка **отключена** | полный extract без лимита символов |

### Сквозной пример: фрагмент `contextFileText`

Фрагмент реального extract (сокращённо; полный прогон — [`ZADACHI_PROBY_EXTRACT.md`](./ZADACHI_PROBY_EXTRACT.md)):

```markdown
5-6 классы

Бараш, Крош, Совунья, Ежик, Пин и Лосяш отправились в поход к Голубому озеру. Перед ними открылся вход в проходную Мышиную пещеру.

Совунья пересекла пещеру за 3 минуты.
Пин затратил 1 минуту.
Крош затратил 2 минуты.

[картинка мультяшной овечки розового цвета с фиолетовыми рогами, улыбкой и поднятой лапой]

Решение:

18 минут.

[иллюстрация синего круглого персонажа с ушами, в красно-желтой кепке]

7-8 классы

Задача про магазин и скидки…
```

**Как читать разметку:**

| Фрагмент | Происхождение |
|----------|----------------|
| Обычный текст абзацев | XML DOCX / текстовый слой PDF |
| `[картинка мультяшной овечки…]` | Vision OCR inline-рисунка в DOCX |
| `Решение:` / `18 минут.` | Текст из файла as-is (позже отфильтруется для Агентов 1–2) |
| Повторяющиеся `[иллюстрация…]` в блоке «Решение» | Vision на каждый рисунок в разборе; все попадают в extract |
| `7-8 классы` | Заголовок блока в исходнике |

Дальше при генерации плана/листа `buildContextReference` **не меняет разметку** `[скобок]` — вырезает блок по классу (если нет пожелания «весь материал») и убирает «Решение:» / ответы (см. [`contextFilter.ts`](../src/data/contextFilter.ts)).
