# Извлечение текста из приложенного файла

## О чём этот документ

На экране создания листа учитель может прикрепить конспект, учебник или скан — Word, PDF или картинку. Сервису нужно **прочитать этот файл и получить обычный текст**, чтобы потом передать его нейросети при генерации заданий. Сам файл ученик не видит: в готовый лист попадают только сгенерированные задания.

Здесь описано **только извлечение текста** — от прикрепления файла до строки в черновике. Как этот текст используется в промптах генерации — в [`PROMPTS.md`](./PROMPTS.md).

### Что внутри

1. **Вход** — какой файл принимаем и как он уходит на сервер.
2. **Выход** — какой JSON возвращается и куда сохраняется на фронте.
3. **Как извлекается текст** — три пути: парсинг Word, текстовый слой PDF, распознавание картинок через vision-модель.
4. **Промпт для модели** — что именно просим вернуть при OCR (полная расшифровка, без пересказа).
5. **Пример на реальном PDF** — полный итоговый `contextFileText`, что есть и чего нет (схемы графов).
6. **Переменные окружения** — какая модель и лимиты задаются в `.env`.

Документ написан как **контракт для разработчиков**: что подать на вход, что ожидать на выходе, без лишней детализации UI.

---

## 1. Вход

**Фронт** отправляет файл при прикреплении на форме Create:

| Параметр | Значение |
|----------|----------|
| Метод | `POST /api/extract-context` |
| Тело | `multipart/form-data`, поле `file` |
| Форматы | `.docx`, `.pdf`, `.jpg`, `.jpeg`, `.png` |
| Размер | до 10 МБ |

Бинарник **не сохраняется** — только результат распознавания.

---

## 2. Выход

**Сервер** возвращает полную расшифровку **без суммаризации**:

```json
{
  "text": "...весь извлечённый текст...",
  "truncated": false
}
```

| Поле | Смысл |
|------|-------|
| `text` | Plain text, до 12 000 символов |
| `truncated` | `true`, если текст обрезан по лимиту |

**Фронт** записывает в черновик:

| Поле черновика | Откуда |
|----------------|--------|
| `contextFileName` | имя загруженного файла |
| `contextFileText` | `text` из ответа (полный extract, или `undefined`) |
| `contextFileNote` | если `text` пустой — «файл приложён, текст не извлечён» |

При генерации листа из `contextFileText` формируется `reference_file.content` / `source_content`: **автоматически убираются решения, ответы, ключи и иллюстрации из них**. Какой раздел файла использовать — указывается в **пожеланиях** (`wishes` → `additional_wishes` в промпте); при совпадении с заголовком блока content обрезается программно.

### Ошибки API

| HTTP | code | Когда |
|------|------|-------|
| 400 | `BAD_REQUEST` | Нет файла / неподдерживаемый формат |
| 413 | `PAYLOAD_TOO_LARGE` | Файл > 10 МБ |
| 503 | `NO_API_KEY` | DOCX, PDF или изображение без ключа на сервере |
| 502 | `EXTRACT_ERROR` | Ошибка извлечения |

---

## 3. Между входом и выходом

Единый vision-путь через **Qwen-VL** (`CONTEXT_OCR_MODEL`). Картинки не игнорируются — модель описывает их в `[квадратных скобках]`.

| Файл | Как извлекается | Модель |
|------|-----------------|--------|
| `.docx` | Обход `document.xml` по порядку: текст параграфов + **Qwen-VL на каждый `r:embed`** на месте рисунка | **Qwen-VL** |
| `.pdf` | **pdf-parse**: текстовый слой + `getScreenshot` → vision OCR по страницам | **Qwen-VL** |
| `.jpg`/`.png` | Vision OCR на изображении | **Qwen-VL** |

Для PDF/DOCX→PDF: до N страниц (`CONTEXT_PDF_MAX_PAGES`, по умолчанию 3), тексты страниц склеиваются через `\n\n---\n\n`. Текстовый слой pdf-parse добавляется **перед** vision-блоком (отключить: `PDF_EXTRACT_TEXT_LAYER=0`).

После любого пути — обрезка до 12 000 символов.

### Особенности

- **DOCX:** без LibreOffice — `docxVision.js` идёт по параграфам и таблицам; **каждый** inline-рисунок (`r:embed`) → `callVisionOcr` → `[описание]` **на месте** в тексте. Кэш по файлу в `word/media/*` — повторная картинка не вызывает API повторно, но `[описание]` вставляется в каждой позиции на листе.
- **Картинки в vision OCR:** модель описывает их в `[квадратных скобках]` — графики с осями, схемы, диаграммы. Не через `![](...)`. `stripMarkdownImages` удаляет только markdown/HTML-картинки, `[описания]` сохраняет.
- **PDF с текстовым слоем:** vision **всегда** вызывается по страницам — графики и иллюстрации попадают в `[скобки]`, а не теряются.

## 4. Промпт для модели (vision OCR)

**Где:** `server/visionOcr.js` → `USER_PROMPT_VISION`  
**Когда:** все форматы с vision (DOCX, PDF, JPG/PNG)  
**Запрос:** `POST {OPENAI_BASE_URL}/chat/completions`, модель `qwen/qwen3-vl-235b-a22b-instruct` (`CONTEXT_OCR_MODEL`), `temperature: 0.1`

Сообщение user состоит из **текста промпта** + **image_url** (base64 data URL).

```
Распознай текст на изображении максимально точно.
Верни только результат без комментариев.
Сохрани структуру документа (абзацы, списки, таблицы).
Используй Markdown.
Все формулы запиши в LaTeX ($...$ и $$...$$). Если в формулах встречаются незнакомые операторы (например, arctg, пиши их в формулах через \operatorname{})

Картинки, фото, схемы, диаграммы, графики, карты, таблицы-изображения и любые нетекстовые фрагменты
не воспроизводи как изображения: для каждого дай описание в квадратных скобках.
Для графиков и диаграмм в [скобках] укажи оси, подписи, ключевые точки и значения, если они читаемы.
Не пропускай иллюстрации — каждая должна получить [описание].
Не используй синтаксис Markdown-картинок (![...](...)) и не вставляй ссылки на файлы или URL.
Не используй маркеры вида [РИС:1] и подобные — только обычные квадратные скобки с описанием.

Никаких пояснений до или после результата, только распознанный текст и описания в скобках.
```

**Что должна вернуть модель:** полный текст страницы в Markdown + LaTeX, без суммаризации и без комментариев. Ответ проходит `stripMarkdownImages` и попадает в `text` ответа API.

## 5. Пример: PDF «Задачи олимпиады» (11 страниц)

Файл: PDF с задачами для 5–6, 7–8 и старших классов. Ниже — **полный итоговый текст**, который попадает в `contextFileText` после прикрепления.

### 5.1. Почему так извлеклось

| | |
|--|--|
| **Метод** | `pdf-parse` (текстовый слой) + **Qwen-VL** vision OCR по каждой странице |
| **Иллюстрации** | Графики и картинки попадают в текст как `[описание в скобках]` |
| **Обрезка** | `truncated: false` — весь текст (~6 500 символов) меньше лимита 12 000 |
| **Фильтрация** | Перед генерацией из content убираются секции «Решение:», ответы и ключи |

```
PDF (11 стр.) → pdf-parse + vision по страницам → contextFileText → source_content
```

### 5.2. Что есть и чего нет в итоговом тексте

| Есть в `contextFileText` | Нет в `contextFileText` (после фильтрации) |
|--------------------------|---------------------------------------------|
| Задача про Смешариков + условие пещеры | Готовые решения и ответы («18 минут») |
| Задача Правдинск/Лжеград + условие | Пошаговые разборы из секций «Решение:» |
| Задача про молочный комбинат | |
| Описания иллюстраций в `[скобках]` | Сами растровые изображения |

Маркеры `-- N of 11 --` — артефакт `pdf-parse`, не часть учебника.

## 6. Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
|------------|----------------------|------------|
| `CONTEXT_OCR_MODEL` | `qwen/qwen3-vl-235b-a22b-instruct` | Vision-модель для PDF-сканов и изображений |
| `CONTEXT_PDF_MAX_PAGES` | `3` | Сколько страниц PDF распознавать через модель |
| `CONTEXT_EXTRACT_TIMEOUT_MS` | `300000` | Таймаут одного OCR-запроса |
| `OPENAI_API_KEY` | — | Ключ OpenRouter (нужен для PDF и картинок) |
| `OPENAI_BASE_URL` | `https://openrouter.ai/api/v1` | URL API |

Задаются в `.env`, `.env.example`, `render.yaml`. Проверка: `GET /health` → поле `ocrModel`.
