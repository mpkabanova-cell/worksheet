## 3. Картинки: inline OCR (после исправления пайплайна)

Строки `502920061341…` — это были **координаты** `<w:drawing>`, когда OCR шёл в конец файла. С **новым `docxVision.js`** (порт ocr_to_doc):

- обход `document.xml` **по порядку**;
- для каждого `r:embed` — **`callVisionOcr`** (тот же промпт, что `/api/process-image`);
- описание вставляется **на месте** рисунка в `[скобках]`;
- кэш по `word/media/*` — одна картинка OCR-ится один раз.

Пример из прогона: после «Из вершины 1…» сразу идёт `[график сети с узлами 1–12…]`, а не `502920061341…`.

Остаётся шум от **декоративных** картинок Смешариков в шаблоне Word и обрезка `truncated: true` при 12 000 символов.

## 5. Почему fallback не работает для этого DOCX

| Причина | Следствие |
|---------|-----------|
| Inline `<w:drawing>` → координаты в текст | Мусор вместо схем |
| OCR только по `word/media/*`, append в конец | Описания не на месте рисунков |
| Нет LibreOffice → нет PDF→vision по страницам | Страница целиком не «видится» |

**Нужный путь:** LibreOffice → PDF → Qwen по каждой странице — тогда схема на странице попадает в `[скобки]` **на месте**, как в промпте `USER_PROMPT_VISION`.

> **Примечание:** в `docxText.js` добавлено удаление `<w:drawing>` до stripXml — координаты больше не попадают в текст, но **содержимое** рисунка по-прежнему нужно получать через PDF-vision или inline OCR.
